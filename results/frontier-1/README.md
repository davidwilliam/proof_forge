# frontier-1: harness changes for sequence-level proofs, measured on hard tasks

The harness changes measured here (commits 1974abd, 2aa8d2a, 7e4c580, 624796d and the plan-text fix c83f2ba) are on branch `experiment/architect-harness`, not on main: they did not reach the goal and regressed on the dev check, so the default harness is unchanged. The per-attempt timeout fix (4ff53f5 on that branch) was applied to main.

Goal: make the repair harness (`agents/repair.py`) prove real tasks that Muse Spark 1.3 does not prove alone (arm A0, `agents/baseline.py`), under the same caps. This directory holds the diagnosis of the earlier hard-task runs, the harness changes, a development-task regression check and the hard-task attempts that were run before the owner paused model runs.

Every run used Muse Spark 1.3 on the Contributor tier (`muse-spark-1.3-contributor`) as prover. List $ is at standard list prices for every model (the budget scale); charged $ is at the tier actually used (Spark on the Contributor tier, Muse Wonder 1.0 at its standard price). The judge, the budget accounting code and every locked task file are unchanged.

## Diagnosis of the earlier runs

Event references are line numbers in each run's `events.jsonl`.

1. The whole-file phase threw away structured progress. When phases 1 and 2 stopped making progress, phase 3 ran the A0 protocol on the rest of the budget, and the run's result was its newest compiling version. In `balancer-1/repair-A1-1` the structured phases had 6 of 8 requirements proved at version 57 (line 389, 2,404 s, about $1.9); the whole-file phase made 55 attempts and the run ended at line 502 with "restore last compiling version", version 113, a 1,304-byte file proving 0 of 8. In `knight-1/A1-2` the whole-file phase (line 470 to 603) took $8.3 of the $9.60 and the result was version 209, a 2,815-byte file (line 604). `compound-1/repair-A1-1` and `A1-2` ended the same way (647 and 1,502 bytes, lines 756 and 757).
2. Each obligation built its own invariant, and none was finished. Every requirement of rc-knight-router and the three reward bounds of rw-compound-comp quantify over every sequence of events, so each needs one inductive invariant. In `knight-1/A1-2` the per-obligation dialogs introduced separate partial invariants (`InvOver` for REQ-NEVER-OVERROUTE, `InvFA` for REQ-FILL-ACCOUNTING, `InvRA` and `InvRAfull` for REQ-ROUTES-AVAILABLE) and 256 distinct helper names in 105 turns. Each dialog had 12 turns and started from scratch, so nothing carried over except banked lemmas. The A0 run that succeeded (`baseline-flagships-1/rc-knight-router/A0-1/final.lean`, lines 123 to 411) wrote one invariant `Inv` of eight conjuncts (counts, per-parent quantities, sent and cumulative quantities equal to the specification's, child records matching, parents in range, sent at most quantity), one preservation lemma per event, `inv_all` by the provided `run_induction`, and each requirement as a corollary. It reached this over 58 whole-file attempts with the whole file and its errors in view.
3. The planner was applied per theorem. In A2 the planner is called only after two direct dialogs on a theorem have failed (pass 1 and the first phase 2 attempt), and only for that theorem. `knight-1/A2-2` succeeded because the first plan (`plan_req_routes_available_0.md`) happened to decompose the invariant preservation by event, and the other requirements reused it; `knight-1/A2-1` built a second invariant for REQ-FILL-ACCOUNTING (`InvFillAcc`) and ran out of dollars with 5 of 6.
4. Budget spent before decomposition. In `compound-1/repair-A2-2` pass 1 took 96 turns, 6,265 s and about $2.7 and proved nothing (line 301: all SORRY); the planner then proved the five per-call requirements and the run stopped at the dollar cap (line 1352) while working on the plan for REQ-REWARDS-BOUNDED, with no shared invariant for the three bounds. In `compound-1` the A1 runs never decomposed anything.
5. Prompt size. Every dialog's first message carried the full spec and the full current file, proofs included. In `compound-1/repair-A2-2` uncached input was $3.04 of the $9.69 (prompts up to 86,614 tokens).
6. Tool friction was not the limit: Lean tool time was 3% to 11% of elapsed time in these runs (244 of 8,147 s in `knight-1/A1-2`, 435 of 4,079 s in `knight-1/A2-2`, 880 of 12,708 s in `compound-1/repair-A2-2`); model latency dominated.

## Harness changes

All are in `agents/repair.py` (and one parameter of `agents/baseline.py`), with tests in `tests/test_harness_architecture.py`. None names a task, a requirement or a proof; nothing from `reference/`, `witnesses/` or `hidden/` is read.

- Joint proof architecture per round (commit 1974abd). Each phase 2 round starts with one call that sees every open required theorem together and returns shared definitions (for example an invariant), helper lemmas stated with `sorry`, and proofs of the required theorems from them. It is installed under the locked statements and kept only if the whole file compiles, so each derivation is checked by Lean before any helper is attempted; otherwise the compiler output goes back to the architect (three tries). The prompt gives general guidance for sequence-quantified requirements: one invariant that holds at the start, is preserved by each operation and implies the requirement; strengthening with equalities to the specification's quantities, bounds and well-formedness; a potential inequality for bounds on accumulating quantities; folds over appended lists for requirements stated from an intermediate state. The architect is the planner model in A2 and the prover in A1. Addresses items 2 and 3.
- Notes across dialogs (1974abd). A dialog that does not prove its target leaves the model's last words and the last tool result; the next dialog on that target, the planner and the architect see them. Addresses item 2.
- A declaration is attempted once per round, and a declaration whose direct dialog already failed goes to the planner first (1974abd). Pass 1 uses 8 turns per obligation instead of 12 (on the dev runs in `results/e1-dev-2`, 256 of the 284 pass 1 successes took at most 8 turns). Addresses item 4.
- Compact prompt view (1974abd). Prompts show proved theorems with their proofs replaced by a marker; definitions, the target and open helpers stay in full, and `read_file` still returns the full file. Addresses item 5.
- Best-version result and a monotone whole-file phase (1974abd). The run's result is the compiling version that proves the most required theorems (the newest on ties), chosen from statuses computed during the run; A0 keeps its newest-version rule. The whole-file phase starts from that version with unused helper theorems removed (kept only if it still compiles and proves as much), and its feedback says when an attempt proves fewer than the best version. Addresses item 1.
- Planner calls capped at 20,000 output tokens and 2 attempts; a failing planner ends that plan, and the architect falls back to the prover (7e4c580). Each attempt is reserved at its worst case and a failed attempt keeps that charge (unchanged accounting); see the first development run below.
- Planner nesting bounded by plan level instead of dependency depth, and open helpers found through helpers that already have complete proofs (624796d). Architecture helpers depend on each other (run lemma, step lemma, one lemma per operation), so with dependency depth the per-operation lemmas were never offered to the planner, and an open helper used only through a proved helper was never attempted.

## The hard-task attempts

rc-knight-router `A2-1`. Pass 1 proved REQ-NORMAL-ORDER-ROUTED. The first architecture call (line 144, `arch_0.md`) produced the structure of the successful A0 proof: an invariant `arch0_Inv` (parent and child counts equal, per-parent quantity, sent and cumulative quantities equal to the specification's for every existing parent, every child record matching its kid with its parent in range, sent at most quantity), a start lemma, one preservation lemma per event, an advance lemma, the run lemma, and derivations of the other five requirements, checked by Lean. Over three rounds the number of helper theorems with complete proofs rose from 14 to 135 to 200 (round records at lines 1019 and 1577), but the preservation lemmas for the parent, route and fill events stayed open after seven planner decompositions (`plan_arch0_inv_*`). In the last failed dialog on the parent lemma its sub-lemmas were proved and the remaining goals were projections of an anonymous structure (`{ st := st, tr := tr }.st.nParents`) that the dialog did not reduce in 12 turns. Round 2 started a fresh architecture and the run reached the dollar cap at line 1670 with 1 of 6; the whole-file phase was not reached.

rw-compound-comp `A2-1`. Pass 1 (8 turns on each of the 8 requirements) proved nothing and took 1,382 s (line 153). The first architecture call was rejected once by the compiler and accepted on the second reply (line 229, 3,124 s, `arch_0.md`): an invariant `arch0_Inv`, a total potential `arch0_totalPot` and a per-account potential `pot`, with lemmas that the potentials bound what is credited, grow by at most the COMP emitted per operation and over a run, start within the amounts owed at the upgrade, and do not grow for an account with no position, plus the per-call effect lemmas; from these it derived all eight required theorems, including REQ-REWARDS-BOUNDED, REQ-ACCOUNT-BOUNDED and REQ-NO-BACKDATED-REWARDS, and Lean accepted the derivations with 29 helpers open. No earlier run on this task reached a checked derivation of the three bounds. The run then resolved helpers in file order and had 8 resolutions succeed (per-call lemmas and planner lemmas for REQ-CALLS-SUCCEED) when it ended at line 606: the next model call received no response within its 600 s per-call timeout, which the harness booked as the run's wall stop at 5,318 s with $6.19 of the dollar cap and 9,082 s of the wall cap unused. Final: 0 of 8 required theorems proved (each derivation depends on open helpers), 33 helper theorems still open in `final.lean`.

A defect found in this run: the architecture prose passed to every helper dialog is taken from the reply that was finally accepted. Here that reply was the correction after a compiler error, so the helper dialogs received one line ("Fixed the rewrite direction in `req_no_backdated`...") instead of the plan. Fixed after these runs in c83f2ba: the helper dialogs get the first reply's plan followed by any corrections.

What the attempts show: the architecture step finds the invariant (and on Compound the potential) that sequence-level requirements need, which the per-obligation loop did not (diagnosis item 2). On Knight, splitting the remaining work into many 12-turn dialogs did not converge on the large preservation lemmas, where the A0 run that succeeded iterated on one file. The changes that would follow from this, not made here because the harness was frozen: longer dialogs or a whole-file stage for the preservation lemmas once an architecture is in place, a cap on the number of helpers per architecture, and keeping one architecture across rounds instead of restating it. On Compound the run ended too early to show whether the helpers are provable.

## Defect: a request timeout ends the run

`Session.call` in `agents/repair.py` books any `DeadlineReached` from `agents/meta_client.py` as the run's wall stop. `meta_client._attempt` raises it not only at the run deadline but also when one attempt gets no complete response within its own per-call timeout (600 s by default), so a single unanswered request ends the run while the deadline is far away. It cut short exactly three recorded runs, all on rw-compound-comp: `results/baseline-flagships-1/rw-compound-comp/A0-1` (9,701 s) and `A0-2` (8,316 s; 600 s after its last attempt) in the main checkout, and `rw-compound-comp/A2-1` here (5,318 s; 600 s between its last event and the stop). The code path is shared by every arm. The measured runs here ran with it; it is fixed after these runs in 4ff53f5 (a per-attempt timeout before the run deadline counts as a lost attempt, keeps its worst-case charge and is retried within the attempt limit; only reaching the run deadline is a wall stop), so Compound A2-1 is not a measurement of what the harness reaches in 14,400 s.
